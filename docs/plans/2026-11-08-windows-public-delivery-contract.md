# Windows Public Delivery Contract

## Problem

The installed Windows candidate has bounded ordinary-web control proof and a
successful explicit GUI stop, but preview packaging cannot be published as a
combined Windows feature. Current release identity2.2.1 belongs to a different
public scheduler artifact. Public privacy copy and optional installer closure
also disagree with the requested combined product.

## Technical Plan

Keep one main and existing preview isolation. Add an explicit Windows public
packaging route with unchanged private-preset, locale, allowlist and vendor
checks. Produce paired GitHub/flat Store extension inventories from the same
final public bytes. Do not infer release authority from a passing local build.

Combined setup delivery must require verified administrator bundle/helper/stager,
source setup ZIP/parent installer and checksums. npm remains independently
versioned; its advertised installation route must acquire or include the exact
verified source closure, never the retired custom launcher. No publication yet.

Canonical English privacy and Store copy must describe selected-account full
file/shell/process scope, separate OS/platform grants, official transport,
protected runtime credentials, local history, Pause/Revoke, restore opt-in and
uninstall boundaries. Keep developer contact/GitHub/LinkedIn prominent.

Main continues exact dedicated-runtime lifecycle tests. No production changes,
unknown-operation replay, blind process termination or authorization expansion.
Use an unused extension version/tag only after authoritative remote checking.

## Alternatives

Renaming a preview ZIP, deleting packaging guards, reusing public2.2.1, shipping
only scheduler capability, or publishing the old native-launcher.exe would not
satisfy the requested Windows delivery and are not selected. Source ZIP may be
clearly extension-scoped if the complete Windows build source is the pinned repo;
do not advertise missing files as a reproducible full Windows source kit.

## Detailed Implementation And Acceptance

1. Packaging worker owns scripts/package.py and its Python packaging tests only.
   Add explicit public Windows mode, negative tests and distribution-pair checks.
2. Disclosure worker owns canonical privacy/Store/README/changelog docs only.
   Review actual code data flows, retain unverified/publication distinctions.
3. Setup worker owns scripts/build-setup-release.py and setup-release tests only.
   Add mandatory combined closure, exact sidecar/checksum tests and fail-closed
   cases; preserve source-only/reparse/binary validation.
4. Main owns version selection, npm contract integration, build orchestration,
   actual UI/runtime acceptance, final integration tests and publication.

Workers edit disjoint files with apply_patch, retain preexisting work, report
red/green commands and exact paths, never mutate Git or installed runtimes, never
read credentials. Independent parallel review is an authorized adaptation of EGM;
main must reconcile actual code and test scope, not accept reviewer votes as proof.
