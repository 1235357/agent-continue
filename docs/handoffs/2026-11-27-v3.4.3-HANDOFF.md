## 2. The Three Bugs to Fix

### Bug 1 — `incidentDeliveries` corruption (`background.js`)
`isIncidentTrace(trace)` returns `true` for `state === 'running'` intermediate snapshots.  
Once delivery completes cleanly, `freshIncidents` is empty → `incidentDeliveries` never pruned → up to 20 frozen `'running'` records evict real incidents.

### Bug 2 — Spurious `unknown-modal` alerts within 5s of START (`dialog-classifier.js`, `content.js`)
`SCAN_DIALOG_CONTEXT { reset: true }` clears `lastKind` but NOT `firstSeenMap` timestamps.  
Also: `detectUnknownModal`/`detectOAuthPopup` don't filter invisible/overlay/zero-sized/closed dialogs.

### Bug 3 — Takeover observer missing turns / observer-adapter split-brain (`content.js`, `adapter.js`, `background.js`)
`document.querySelector(busyControlSelector)` matches hidden/sidebar `.typing-indicator` even when no Stop button exists.  
`text.length > 4000` silently drops long Dot turns. No trailing user-turn dominance. `lastTakeoverToken` latched prematurely. `trigger: 'round'` hardcoded on `takeover-replied`.

## 3. Round 3 Blocking Issues — MUST Fix in Design Before Implementation

> These are findings from EGM Round 3 (Comprehension `b1c7e415`, Criticism `72511e48`). The Readiness reviewer `23112613` did NOT complete due to quota exhaustion.

### F1 (HIGH, BLOCKING) — `pointer-events: none` check on ancestors
**Problem**: Design line 58 checks `st.pointerEvents === 'none'` across the **entire** ancestor loop in `isVisibleBlockingDialog()`. CSS `pointer-events` is inherited — a Radix/Tailwind portal wrapper with `pointer-events: none` and inner `[role="dialog"]` with `pointer-events: auto` will falsely reject real OAuth dialogs.  
**Fix**: Check `pointer-events` only on `dialog` itself (`node === dialog`), not on ancestors.

### F2 (HIGH, BLOCKING) — No retry mechanism when `reply?.transient === true`
**Problem**: Design says latch `lastTakeoverToken` only when `reply?.transient !== true` — but there is **no retry mechanism**. When `job.phase === 'sending'` and `TAKEOVER_PROMPT_OBSERVED` arrives, `background.js` returns `{ok:false, transient:true}`, page goes quiescent, and `content.js` never retries.  
**Fix**: On `reply?.transient === true`, call `scheduleDialogCheck(1500)` in `content.js` AND/OR `pingDialogObserver(tab.id, false)` in `background.js` when `sending → idle` transition completes.

### F3 (HIGH, BLOCKING) — `handlePagePromptObserved()` check order
**Problem**: `job.phase !== 'idle'` checked too early — opted-out / capped / foreign-tab callers receive `transient:true` during active send, causing spurious retries.  
**Fix**: Check order must be: `job.enabled` → tab/URL binding → `autoAuthorizeTakeover` → `consecutiveTakeoverReplies < 3` → **THEN** `job.phase !== 'idle'`.

### F4 (HIGH, BLOCKING) — `else if` starvation of takeover observer
**Problem**: `hasUnansweredRoutineToolCard()` is an `else if` gate — when it fires (even if rejected by background.js), `observeIdleTakeoverPrompt()` is NEVER called. Also `hasUnansweredRoutineToolCard()` doesn't use `isVisibleNonOverlay`, so invisible/hidden tool cards can permanently starve takeover detection.  
**Fix**: Decouple — always call both. At minimum, also call `observeIdleTakeoverPrompt()` when `ROUTINE_APPROVAL_OBSERVED` is rejected.

### F5 (HIGH, BLOCKING) — Multiple `adapter.js`/`content.js` selector parity gaps
Five sub-issues:
- `adapter.js:findDotSignInCard()` `userTurns`/`btns`/`curr` unfiltered for overlays
- `adapter.js:visible()` / `visibleMainMatches()` don't exclude `nav, aside, [inert], [aria-hidden="true"]`
- `content.js` `composerEditorSelector` includes `<textarea>` but `adapter.js` excludes it on Dot
- `adapter.js:266` `sendSelector` has `button[aria-label*="Send" i]` which matches `"Send feedback"` (bypasses `.typing-indicator` guard)
- Fixed-portal detection: design omits `!ancestor.contains(mainEditor)` guard from `adapter.js:234-240`

### F7 (MEDIUM) — `oauth-popup` `lastKind` stuck
`handleDialogException()` delegates `oauth-popup` to `handlePagePromptObserved()`. If this returns `{transient:true}`, `lastKind` sticks on `'oauth-popup'` and suppresses takeover observer permanently.

### F6 (MEDIUM) — `persistDeliveryTrace()` lazy pruning gap
Upgraded `v3.4.2` users who export diagnostics before first send still see corrupt `'running'` records.  
`nextInc.sort((a,b)=>a.sequence-b.sequence).slice(-20)` can evict new incidents if `diagnosticSequence` resets.  
Consider `initialize()` pruning and `startedAt`-based sort.
