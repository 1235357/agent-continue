## 2. The Three Original Bugs to Fix (from production traces)

### Bug 1 — `incidentDeliveries` corruption (`background.js`)
`isIncidentTrace(trace)` returns `true` for `state === 'running'` intermediate snapshots.  
Once delivery completes cleanly, `freshIncidents` is empty → `incidentDeliveries` never pruned → up to 20 frozen `'running'` records evict real incidents.

### Bug 2 — Spurious `unknown-modal` alerts within 5s of START (`dialog-classifier.js`, `content.js`)
`SCAN_DIALOG_CONTEXT { reset: true }` clears `lastKind` but NOT `firstSeenMap` timestamps.  
`detectUnknownModal`/`detectOAuthPopup` don't filter invisible/overlay/zero-sized/closed dialogs.

### Bug 3 — Takeover observer missing turns / observer-adapter split-brain (`content.js`, `adapter.js`, `background.js`)
`document.querySelector(busyControlSelector)` matches hidden/sidebar `.typing-indicator`.  
`text.length > 4000` silently drops long Dot turns. No trailing user-turn dominance. `lastTakeoverToken` latched prematurely. `trigger: 'round'` hardcoded on `takeover-replied`.

## 3. Round 7 Blocking Issues — Must Fix in Design (Revision 9)

> From Round 7 Criticism reviewer (`2ca8da35-27b1-45cb-93cd-c9f323636ab3`), 2026-11-28 06:14 UTC

### B1 (BLOCKER) — `dotCardTokenMap.get(dlg)` caches stale token across `forceMount` dialog cycles
- **Files**: `docs/DESIGN-v3.4.3-OBSERVER-AND-TELEMETRY.md:200`, `adapter.js:485-489`, `adapter.js:511-515`, `content.js:128-132`
- **Problem**: React/Radix `forceMount` persistent `[role="dialog"]` elements stay mounted across open/close cycles. `dotCardTokenMap.get(dlg)` returns the cached Turn-1 token (`'card:1:...'`) forever — even after `userCount` increments to `2+` or `dlgText` changes. When the modal closes (`content.js` clears `lastTakeoverToken` for `dialog:` per line 158) and reopens on a later turn, `adapter.js` returns the stale cached token (`=== args.lastTakeoverToken`), suppresses the recurring modal to `'ready'`, and `handlePagePromptObserved()` returns `{ ok: true, handled: true }` — permanently latching `content.js`.
- **Fix**: Do NOT cache the `WeakMap` entry for `dialogs` by `dlg` reference alone. Compute `'card:' + userCount + ':' + clean(dlgText).slice(0, 120)` directly on every call, OR key the cached entry on `${userCount}:${clean(dlgText).slice(0, 120)}`. Ensure `userTurns` / `userCount` is computed **before** the `dialogs` loop at `adapter.js:479`.

### B2 (BLOCKER) — `content.js:isElementVisible()` missing `display: contents` branch
- **Files**: `docs/DESIGN-v3.4.3-OBSERVER-AND-TELEMETRY.md:119` vs `L90` and `L196`
- **Problem**: `dialog-classifier.js:isVisibleBlockingDialog()` and `adapter.js:visible()` both handle `display: contents` wrappers (which return empty `getClientRects()`, `0x0` bounding rect, 0 `offsetWidth/Height` in Chromium). `content.js:isElementVisible()` does not — if any `[role="dialog"]`, inline card, message row, or `[data-composer-root]` wrapper uses `display: contents`, `adapter.js:visible()` returns `true` while `content.js:isElementVisible()` returns `false`, blinding `hasUnansweredRoutineToolCard()`, `observeIdleTakeoverPrompt()`, `resolveMainEditor()`, and `isIdleForTakeover()`.
- **Fix**: Add the same non-hidden `display: contents` descendant / `Range` box (`>= 1x1`) check to `content.js:isElementVisible()`, mirroring `adapter.js:visible()` exactly.

### B3 (BLOCKER) — `adapter.js:findApprovalPrompt()` missing `!isInOverlay()` on standalone Dot inline-card discovery
- **Files**: `docs/DESIGN-v3.4.3-OBSERVER-AND-TELEMETRY.md:197` vs `L129-130`, `adapter.js:855-880`, `adapter.js:1008-1012`
- **Problem**: `content.js:hasUnansweredRoutineToolCard()` filters all inline-card buttons via `isVisibleNonOverlay(..., { allowOverlay: false, overlayRoots })`. `adapter.js:findApprovalPrompt()` applies overlay/sidebar filtering to `recentAssistantTurns` and `dialogs` but NOT to the `isDot` standalone card discovery loop (`L855-880`, `feedNode` can be `document` or contain a `position: fixed` floating overlay inside `<main>`) or `standaloneDotPair` (`L1008-1012`). A `position: fixed` Citation/sub-thread overlay (not `role="dialog"`) containing quoted Dot approval buttons would be ignored by `content.js` but detected and clicked by `adapter.js` — violating overlay isolation.
- **Fix**: Compute `const isInOverlay = currentOverlayScope();` inside `findApprovalPrompt()` and enforce `!isInOverlay(el)` / `!isInOverlay(curr)` in the `L864-878` standalone Dot card discovery loop, and `!isInOverlay(el)` for non-dialog roots in `scanRoot` / `standaloneDotPair` at `L1008-1012`.

## 4. Round 7 Non-Blocking Concerns (address opportunistically)

1. **`signal.aborted` dead property**: `persistDeliveryTrace()` checks `signal.aborted` but `invalidation()` at `background.js:104-121` has no `.aborted` property. Currently harmless (epoch check catches it), but add `get aborted() { return invalidated; }` to `invalidation()` or drop the check.
2. **Stale `lastMaskToken`/`lastMaskCount` on cleared `oauth-popup`**: After 3 `handled: false` retries on `oauth-popup`, if popup closes and later reopens, `lastMaskCount >= 3` gives 0 retries. Clear `lastMaskToken`/`lastMaskCount` when `!kind` (Step 3 mask token scope).
3. **`content.js:observeIdleTakeoverPrompt()` map-vs-filter wording** (`L182, L186`): Keep `turns` as the row array; set `body = last.querySelector?.('.message-body') || last` after iteration — do not map `el` → `.message-body` before `.at(-1)`.
4. **Minor regex gap**: `content.js:51` `signInButtonPattern` includes `give control back | hand back | return control`; `adapter.js:412` `dotInlineAuthButtonPattern` omits them. Edge case only; no retry loop risk.
