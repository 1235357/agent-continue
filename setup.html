If setup is unclear, do not delete the directory or reinstall. This read-only command checks configuration, bridge files and registration separately. It does not connect or retry; a pass is not proof of browser launch or chat authorization.

Windows local controls

Understand device access

The intended access includes account-level file, terminal and process operations, not just status checks. Tools run on the target device as the selected operating-system account; when explicitly configured as administrator or root, they can modify system files and settings.

Selecting or binding a conversation does not grant device access. Operating-system approval in the installer and tool authorization in ChatGPT remain separate steps for both Dot and ordinary chats.

Desktop Commander's upstream policy states that telemetry is enabled by default. The integrated installer must handle installation scripts and privacy configuration before first execution and verify the disabled state; this integration is not deployed by this candidate. Do not share raw tool-call history, which can contain command arguments and results.

Setup request

The request contains only the target platform, current extension ID and fixed bridge identity. It contains no keys, commands or file paths and does not authorize installation or elevation.

The Windows and remote Linux source consumers can generate read-only plans for their respective targets. macOS and local Linux requests are currently handoff metadata only; each consumer rejects other targets.

Connection sequence

On macOS, install the official client with brew install openai/tools/tunnel-client; do not bypass Gatekeeper. Installing the official client does not install this extension's native bridge. In stdio mode, keep only one active runtime per tunnel; stop the old instance before replacing it.

  1. Verify the extension identity. Review and install the local component on the target device; operating-system approval and browser permission are separate steps. The extension cannot install its own first native host.
  2. After local bridge installation, explicitly request optional browser permission and check status on Devices. Browser approval does not prove installation succeeded.
  3. Review and deploy the service components directly on the Linux server; local browser bridge permission is not a prerequisite. This candidate provides no automatic installer and does not relay connections through Windows.
  4. Configure the official tunnel and MCP on the target device. Keep the runtime key in protected device storage, never in the extension, request file or chat. Run only one instance for a stdio tunnel.
  5. Connect ChatGPT and Dot

Connect ChatGPT and Dot

  1. Prepare a dedicated tunnel. Create a tunnel in OpenAI Platform and associate it with the ChatGPT workspace that will use the plugin. Keep the restricted runtime key on the target device and enter only the key-file path in the terminal. Do not paste the runtime key into the extension, a chat, or a setup request.
  2. Confirm the device is connected. Connect the official tunnel on the target device and check its status. For browser-managed Windows, connect from Devices; standalone mode does not need the Chrome bridge. A ready device does not mean any chat is authorized.
  3. Create a private plugin in the matching workspace. Open ChatGPT Plugins. Add a custom MCP server, select Tunnel as the connection type, and choose your tunnel. Review the authentication and access settings. Do not substitute an existing production plugin for testing.
  4. Verify both chat surfaces. Select the plugin in an ordinary ChatGPT chat and separately in Dot. Approve only one read of a disposable, non-sensitive text file on the target device. Check the actual read_file tool result for the plugin, file path, and returned contents. Do not include the expected contents in the request. A model reply or a pass on the other surface is not verification.
Tunnel or tools missing?

Tunnel not listed: check the target ChatGPT workspace association and the plugin creator's Tunnels Read + Use permissions.

Plugin created but tools missing: confirm the device tunnel is still online and check whether this chat offers the plugin. If Dot does not offer the plugin, Dot remains unverified; do not reinstall the device for this reason.

Remote Linux request handoff instructions

This read-only source consumer is not an installer. First review the trusted bootstrap source and offline source package on the server; independently verify the manifest digest rather than treating the request as trust evidence.

python3 /reviewed-bootstrap/setup_plan.py \
  --request-file /absolute/path/agent-continue-setup-request.json \
  --package-root /absolute/path/reviewed-source \
  --manifest-sha256 <independently-reviewed-64-character-digest>

File paths and the manifest digest are supplied only on the server, not added to the extension request. The consumer does not access the network, execute package code, or install, start or resume a tunnel.

readyToApply=false is always retained. Successful source verification does not prove device installation, tunnel readiness or chat authorization; subsequent steps require separate acceptance.

Run the verified setup source bundle on the server, with its own tunnel and a key file stored only on that server. Setup does not start the tunnel, install a service or authorize chats.

node /absolute/setup/bin.mjs setup-server \
  --install-dir "$HOME/.agent-continue-server" \
  --setup-request /absolute/path/agent-continue-setup-request.json \
  --tunnel-id tunnel_REPLACE_WITH_SERVER_TUNNEL_ID \
  --runtime-key-file /absolute/private/server-runtime-key.txt \
  --consent full-account

Optional remote management

Server MCP tool data goes directly to official OpenAI, without a Windows relay or local browser bridge; local native permission is not a prerequisite for server tool installation.

Browser-driven pause and reconnect are a separate optional lifecycle-management path: they require an installed local native manager, allowed nativeMessaging, independently verified SSH host keys and an OS agent ready for on-demand SSH authentication. This page does not install, request permission or call native code.

For the optional local manager, separately export a matching local-platform request, not the linux-server request; keep the server request for the server. setup-manager needs no local OpenAI runtime key and does not download a tunnel client; it prepares only private state and the extension binding, and native registration remains separate.

node /reviewed-bootstrap/bin.mjs setup-manager \
  --install-dir <absolute-new-local-manager-install-dir> \
  --consent full-account \
  --setup-request <absolute-local-platform-request.json>

Review and run the source bootstrap command only at a trusted local entry. The paths, host, port, account and digest below are not added to the browser request; do not enter host keys, private keys or runtime keys on this page or in chat. The digest must come from independent verification, not from trusting the command itself.

node /reviewed-bootstrap/bin.mjs enroll-ssh \
  --install-dir <absolute-local-manager-install-dir> \
  --consent full-account \
  --ssh-executable <absolute-local-ssh-executable> \
  --host <verified-server-host> \
  --port <canonical-decimal-port> \
  --user <server-os-account> \
  --remote-node <absolute-posix-node-path> \
  --remote-install-dir <absolute-posix-server-install-dir> \
  --known-hosts <absolute-local-known-hosts-file> \
  --known-hosts-sha256 <independently-reviewed-64-character-digest>

This is source guidance with no released installer or runnable public npx command, not an on-site installation. enroll-ssh does not establish SSH connections or start services. The returned deviceUrl conveys selection only: the device is not connected, authenticated or authorized by this link; SSH authentication, device reachability, native registration and chat tool authorization need separate verification.

Temporary browser controls

Management panel

Local runtime readiness does not verify ChatGPT or Dot authorization.

The control session ends after 15 minutes or when you press Enter or Ctrl+C in the terminal. Closing the panel or ending the session does not change the tunnel connection; an action already submitted may still finish.

Reopen a temporary control session

If you skipped pairing, did not see the prompt, or the session ended, run this command in an interactive terminal while the device manager is running.

.\install.ps1 -DeviceAction browser -Consent accept-control

If the panel cannot recover the receipt, query the operation ID on the original device. This does not replay the action. The terminal pause command remains available for urgent disconnection.

.\install.ps1 -DeviceAction status -OperationId '<operation ID>'
.\install.ps1 -DeviceAction disconnect-and-pause -Consent accept-control
